# Данные и приватность VKN

Обновлено: 29 октября 2026 года. Документ описывает VKN для Windows, Linux и Android. Автор проекта: gr4shin.

## Получает ли автор данные приложения

В Android сессия хранится в приватном каталоге без резервного копирования, зашифрованная AES-GCM с ключом Android Keystore. Аудио и обложки сохраняются отдельными файлами в `noBackupFilesDir/media-cache`; аудиокэш разделён по аккаунтам. Медиафайлы дополнительно не шифруются. WebView хранит настройки и снимки страниц локально; входящий access token доступен интерфейсу приложения, refresh/safety и обновление сессии обрабатывает нативный мост. Обложка, название, исполнитель и состояние воспроизведения передаются локальной MediaSession Android для системного управления музыкой. Это не отправка данных автору. Discord в Android не подключён.

По отдельному действию скачивания Android сохраняет MP3/M4A в общую папку `Music/VKN` и регистрирует название и исполнителя в локальном MediaStore. Эти файлы доступны другим приложениям с соответствующим доступом к музыке и остаются после удаления VKN; очистка внутреннего кэша их не удаляет. История очереди хранится в приватном `noBackupFilesDir/download-queue.json`, отдельно по аккаунтам, без токенов и потоковых URL. Открытие готового файла передаёт выбранному приложению временное разрешение чтения. Для нового трека используются те же серверы VK/CDN, отдельного сервера конвертации нет.

VKN не отправляет автору аналитику использования, телеметрию, историю прослушиваний, содержимое библиотеки или токены VK. В текущей версии нет встроенного сервиса удалённой аналитики и автоматической отправки отчётов об ошибках на сервер автора.

Участие OpenAI Codex и Anthropic Claude в разработке не добавляет сетевые обращения к OpenAI или Anthropic в установленное приложение.

## Куда направляются сетевые запросы

| Получатель | Когда | Какие сведения передаются и зачем |
| --- | --- | --- |
| GitHub: `api.github.com` | Фоновая проверка обновлений после запуска и примерно раз в четыре часа работы при доступной сети и видимом приложении | Публичные запросы последнего релиза `gr4shin/vkn` и метаданных его тега. Токен VK, профиль, библиотека и установленная версия не отправляются; cookies не используются. GitHub видит IP-адрес и технические заголовки HTTP. Кнопка уведомления открывает страницу релиза в браузере |
| VK: `api.vk.ru`, `id.vk.ru`, `login.vk.ru` | Вход, проверка и обновление сессии, загрузка библиотеки, поиск, каталог и действия аккаунта | Данные QR/токен-сессии, cookies по правилам домена, идентификаторы аккаунта и объектов, поисковые запросы и параметры соответствующего действия. Для авторизации и выполнения запросов VK |
| Медиа-серверы и CDN по адресам из ответов VK | Воспроизведение, загрузка обложек, локальный кэш и скачивание | Запрос конкретного изображения или аудиоресурса, включая параметры полученного URL; получатель видит сетевой адрес и обычные технические сведения HTTP |
| Серверы выбранных радиостанций | Прослушивание радио | Запрос потока выбранной станции; фактический получатель определяется её URL |
| Локальный клиент Discord, далее сервис Discord | Только при включении Rich Presence | Выбранные настройками поля: название и исполнитель, источник/коллекция, прогресс, обложка и публичные ссылки VK. Для отображения музыкальной активности. Токен аккаунта Discord VKN не запрашивает |
| VK | Только при включении трансляции текущего трека | Идентификатор аудио, выбранные страницы и параметры трансляции. Для обновления музыкальной активности VK |
| Приложения VKN в локальной сети | Только при включении VKN Connect (бета) | Обнаружение устройств, имя устройства и ID аккаунта, подтверждение связи, очередь и состояние воспроизведения, команды управления. Токен VK и потоковые ссылки не передаются; проигрывающее приложение обращается к VK со своей сессией |
| Браузер телефона в локальной сети | Только при включении отдельного веб-пульта | Состояние плеера, метаданные трека, обложка, доступный текст песни и команды управления. Страницу обслуживает сам VKN на компьютере; звук остаётся на компьютере |
| Сайт, который пользователь открывает в браузере | Переход по внешней ссылке, в том числе ссылка справки входа на `vkhost.github.io` | Браузер обращается к выбранному сайту. Его обработка данных определяется самим сайтом |

VK и другие сетевые получатели могут видеть IP-адрес и технические заголовки запроса, а VK связывает авторизованные действия с аккаунтом. Отсутствие аналитики автора не означает отсутствие обработки данных со стороны этих сервисов. Доступность сетевых функций определяется VK, аккаунтом и выбранными внешними сервисами.

## Что хранится на устройстве

| Данные | Хранение и назначение |
| --- | --- |
| Сессия VK | `auth-state.json` в локальном профиле приложения. В текущем формате сессия шифруется средствами Electron safeStorage с системным провайдером, чтобы восстанавливать вход и обновлять токен |
| Настройки | Локальные файлы настроек и браузерное хранилище встроенного интерфейса: тема, звук, приватность интеграций, кэш и другие параметры |
| Очередь и навигация | Локальный снимок треков, позиции, режима, вкладок и закреплений, чтобы продолжать предыдущий сеанс |
| Снимки страниц и библиотека | IndexedDB и локальные снимки API, чтобы показывать ранее загруженные данные и работать при временном отсутствии сети |
| Аудио и изображения | Дисковый медиакэш для воспроизведения и уменьшения повторных загрузок. При сохранении HLS в него могут входить сегменты, служебные данные и ключи полученного потока |
| Статистика прослушиваний | Локальное хранилище отдельно по аккаунту: треки, источники, время и количество прослушиваний. Для личной сводки пользователя; на сервер автора не передаётся |
| Скачанные файлы | MP3 в выбранном пользователем месте. Локальный индекс хранит связи с готовыми файлами, а снимок незавершённых загрузок — их состояние и пути |
| Диагностические логи | Файловая запись, включая предупреждения и ошибки, включается только пользователем. На Windows/Linux журнал хранится отдельно для аккаунта в его каталоге `diagnostics` |
| VKN Connect и веб-пульт | Параметры и доверенные устройства сохраняются локально. На Windows/Linux файлы раздельны по аккаунтам и используют системное шифрование; Android защищает ключ связи средствами Android Keystore |

Локальный профиль находится в каталоге данных приложения внутри профиля вашей ОС (`userData` Electron). Точное имя и расположение зависят от сборки и системы; MP3 и экспортированные файлы находятся там, где их сохранил пользователь.

На Windows/Linux каждый аккаунт использует отдельную базу библиотеки, каталог аудио и обложек со своими лимитами, настройки, историю и доверие Connect. До определения аккаунта используется нейтральная гостевая область. При смене аккаунта прежние подключения Connect и веб-пульта не передаются новому владельцу. При обновлении доказанно принадлежащие аккаунту старые данные копируются в его область; источники сохраняются для безопасного перехода. Старые обложки и журналы без известного владельца автоматически не приписываются одному аккаунту.

Шифрование сессии не распространяется на весь профиль. Кэш, снимки страниц, настройки, статистика и скачанные MP3 не имеют общего шифрования VKN. Пользователь устройства, вредоносное ПО или программа с соответствующим доступом могут прочитать эти данные. Системная защита сессии также не защищает от всех угроз внутри уже доступного пользовательского сеанса. При недоступности защищённого системного хранилища новая сессия не сохраняется открытым текстом.

## Локальная статистика

Учёт прослушиваний включён по умолчанию. Его можно отключить в настройках хранения; ранее записанные сведения удаляются отдельным действием очистки статистики. Отключение само по себе не удаляет историю.

В текущем формате хранится до 20 000 подробных записей; объём дополнительно ограничен при сохранении. Старые подробности могут удаляться, при этом общие счётчики сохраняются. Экспорт статистики создаёт выбранный пользователем локальный JSON-файл.

Это функция для пользователя. Автор не получает её содержимое, рейтинги или счётчики автоматически.

## Диагностика и обращения автору

Диагностические логи выключены по умолчанию. При включении они сохраняются локально: не более трёх файлов по 2 MiB. Журналы содержат технические события, а не полный дамп библиотеки. Перед записью и экспортом приложение маскирует известные токены, cookies, данные авторизации и другие чувствительные поля.

Экспорт включает версии приложения, Electron/Chromium, платформу, архитектуру, локаль и технические записи. Он сохраняет файл через системный диалог и не отправляет его автоматически. Маскирование ограничено известными полями и форматами; оно не гарантирует распознавание любой личной информации в произвольной строке. Проверяйте файл перед передачей.

Автор получает сведения, если вы сами направляете ему обращение, текст, снимки или файл. Содержание добровольного обращения используется для рассмотрения проблемы, воспроизведения ошибки и исправления приложения. Публикация Issue на GitHub может сделать текст и вложения доступными другим людям; не размещайте там секреты или сессию.

## Управление и удаление

- Обычное удаление сохранённого аккаунта не является полной очисткой его локальных данных.
- На Windows/Linux действие «Удалить аккаунт и его данные» требует подтверждения и удаляет его сохранённую сессию, базу библиотеки, кэш, настройки, историю, очереди, журналы и доверие Connect/веб-пульта. Принадлежащие ему записи в старых источниках миграции также удаляются; данные других аккаунтов сохраняются.
- Кэш аудио и обложек очищается в настройках хранения. Статистика удаляется своим действием очистки.
- Выключение диагностики прекращает запись всех файловых журналов. Уже записанные файлы остаются до отдельной очистки; автоматической отправки нет.
- Отключение Discord прекращает публикацию новой активности через эту интеграцию. Настройки позволяют скрывать отдельные поля.
- Чтобы удалить весь профиль, включая служебные данные приложения и старые файлы без установленного владельца, закройте VKN и удалите каталог его данных. Самостоятельно сохранённые MP3/M4A и экспортированные JSON/логи нужно удалить из выбранных папок отдельно. Удаление программы не следует считать гарантией удаления профиля. Действие полного удаления одного аккаунта сейчас доступно на Windows/Linux; Android позволяет очистить данные приложения средствами системы.

Удаление локального файла не удаляет уже переданные сведения с серверов VK, Discord или GitHub. Правила и сроки их хранения определяют эти сервисы.

## Скачивание релизов и сторонние сайты

При просмотре GitHub и скачивании релиза запрос получает GitHub. Сайт может обрабатывать технические сведения о посещении и скачивании по своим правилам. Эти запросы не являются отправкой истории прослушиваний из VKN.

Автоматический updater в текущем VKN не реализован. Размещение новой сборки на GitHub само по себе не добавляет фоновые обращения установленного приложения к GitHub.

Обработка данных на GitHub описана в [политике GitHub](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement). VK, Discord, радио и другие открываемые сайты применяют собственные правила.

## Границы документа

Документ описывает фактическое поведение текущего приложения, а не обещает полную анонимность, абсолютную безопасность или работу всей музыкальной службы без сети. Локальный интерфейс и сохранённые данные могут работать автономно; вход, обновление библиотеки и получение новых потоков требуют VK.

Разработческий запуск отличается от официального дистрибутива: в DEV доступны console, инструменты сбора сырых ответов VK и отдельные локальные дампы. Эти инструменты отключены в упакованном приложении и не входят в обычный диагностический экспорт.
